# USB Android AI Controller

Desktop-программа на Python для управления Android телефоном по USB через ADB. Встраивает видеопоток scrcpy в окно, принимает команды, нажатия и свайпы мышью и может использовать vision-модель через API.

## Запуск на Windows

1. Установите Python 3.10 или новее.
2. Установите **Android SDK Platform-Tools**. Путь к `adb.exe` можно добавить в `PATH`, положить `adb.exe` и `fastboot.exe` в `platform-tools` рядом с `main.py` или указать путь к `adb.exe` прямо в поле приложения через кнопку **Обзор…**. Если `fastboot.exe` лежит рядом с выбранным `adb.exe`, приложение найдёт его автоматически.
3. Установите [scrcpy из официальных выпусков](https://github.com/Genymobile/scrcpy/releases). Путь к `scrcpy.exe` можно оставить в `PATH`, положить рядом с `adb.exe` или выбрать в отдельном поле приложения.
4. На телефоне включите параметры разработчика и USB debugging, подключите кабель с передачей данных, разблокируйте экран и подтвердите RSA запрос отладочного компьютера.
5. В папке проекта выполните:

   ```powershell
   python -m pip install -r requirements.txt
   python main.py
   ```

Путь к ADB сохраняется в `settings.json`. Проверьте, что `adb devices -l` показывает телефон со статусом `device`. Если статус `unauthorized`, подтвердите запрос на экране телефона. При первом подключении нажмите **Подключить / запустить ADB**.

## Что умеет

- Показывать нативный видеопоток scrcpy поверх области экрана AndAI: окно выравнивается по панели и следует за ней при перемещении и изменении размера приложения. Live-отладка рисует прозрачный слой прямо поверх scrcpy; касания проходят сквозь слой в телефон.
- Нажимать и свайпать по кадру мышью, нажимать Power, громкость и системные кнопки навигации.
- Вводить команды AI на русском языке; vision-модель может использовать скриншот и вызывать ограниченный набор действий ADB.
- Переключать Wi-Fi и мобильные данные там, где версия Android и производитель разрешают это ADB shell-командам.
- Включать и выключать Bluetooth через Android shell-команду; доступность зависит от прошивки телефона.
- Перезагружать телефон в систему, Recovery или bootloader/Fastboot.

## Локальный мозг без API key

По умолчанию выбран локальный режим. Он не требует ключа или интернета: распознаёт небольшой набор однозначных команд и выполняет правила, которые вы добавили кнопкой **Обучить пример**. Правила сохраняются в отдельный JSON файл; путь можно выбрать в поле файла мозга. **Сохранить мозг** создаёт файл, даже если правил пока нет.

Для обучающего примера задайте фразу и команды по одной на строку. Поддерживаются:

```text
tap 500 900
swipe 500 1400 500 400 500
hold 500 900 1200
press power
press volume_up long
wifi off
data on
bluetooth on
reboot fastboot
reboot system
type Привет
app com.android.settings
```

При включённой полной автономии добавляются команды `shell <команда>`, `adb shell <команда>` и `fastboot <команда>`. Например, `shell getprop ro.product.model` или `fastboot getvar product`. Их можно выполнять напрямую без обучения либо сохранить в правило. Эти явные команды доступны и локальному мозгу без API; он не начинает сам придумывать задачи и планы.

Фраза правила срабатывает, если встречается в запросе. Базовый словарь русских и английских терминов находится в `dictionary.json`: локальные команды и обученные фразы распознаются на обоих языках. Локальный режим не является нейросетью, не анализирует скриншот и не понимает произвольные формулировки: для новой задачи добавьте правило. Он сохраняет заданные вами действия в JSON и выполняет их через тот же набор ADB функций.

## Самообучение и отладка экрана

Кнопка **Самообучение: записать пример** попросит фразу-триггер и оставит поток scrcpy активным. Касания и свайпы по зеркалу внутри AndAI записываются вместе с действиями кнопок и переключателей. Если управлять напрямую из отдельного окна scrcpy, эти жесты в пример не попадут. Нажмите **Остановить и сохранить**: последовательность попадёт в JSON-файл мозга и будет воспроизводиться по этой фразе в локальном режиме без API-ключа. Это запись демонстрации, а не обучение весов нейросети. Вводимый текст и произвольные shell/Fastboot-команды в пример не сохраняются.

Кнопка **Включить live-отладку** рисует рамки UI поверх scrcpy: бирюзовые — элементы Android, оранжевые — OCR-текст. Интерфейсные рамки извлекаются из accessibility-дерева Android, текстовые — через OCR. В исследовательском режиме отдельное окно мыслей кратко описывает распознанные надписи, совпадения RU/EN словаря и найденные ранее экраны; распознанный текст также извлекается из дерева Android, если OCR недоступен. Память `screen_memory.json` хранит распознанный текст, совпадения словаря, действия и компактный визуальный отпечаток экранов; путь можно сменить в поле памяти. Технические события остаются в журнале.

Для OCR нужен установленный Tesseract OCR; русская и английская модели уже лежат в папке `tessdata` проекта, а приложение передаёт её путь напрямую, не полагаясь на `TESSDATA_PREFIX`. `pytesseract` устанавливается из `requirements.txt`. Файлы моделей взяты из [официального tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) под Apache-2.0; копия лицензии находится в `tessdata/LICENSE`.

Совпадения словаря RU/EN показываются прямо под полем задачи; панель **Наблюдения и выполненные шаги** отображает статус, распознанные слова, OCR и вызовы действий. В консоль они печатаются при запуске через `python main.py`. Это короткие журнальные записи и сводки, без внутренней скрытой цепочки рассуждений модели.

В поле под словарём можно вставить прямую ссылку на JSON, TEI/XML, CSV или TXT и нажать **Скачать по URL**. Кнопка **Импортировать файл** загружает такой же файл с компьютера. Новые слова сохраняются отдельно в `downloaded_dictionary.json`, объединяются с базовым словарём и сразу участвуют в поиске совпадений. Для TEI/XML, CSV и TXT лимит — 1 ГБ, эти форматы разбираются потоково; JSON ограничен 128 МБ. Англо-русский TEI/XML словарь FreeDict можно найти на [странице файлов FreeDict](https://download.freedict.org/generated/eng-rus/). Импорт словаря расширяет поиск терминов, но не добавляет команды управления телефоном.

## Диалог и режим любопытства

Поле ввода и окно **Диалог с ИИ** работают как переписка: модель помнит последние сообщения, отвечает на обычные вопросы и может выполнить просьбу на телефоне. Выберите **Ollama / Qwen** для локального диалога без API-ключа либо **OpenAI API**. Режим **Torch / случайная модель** предназначен для экспериментов с необученной сетью и не умеет вести диалог.

Флажок **Режим любопытства** включает исследование, а кнопка **Исследовать экран** запускает его. Цикл продолжается до нажатия **Остановить исследование** и может выполнять любые действия через интерфейс, ADB shell и Fastboot. Единственное ограничение — запрет инициировать вызов экстренным службам; для экранных вызовов есть OCR-проверка, а прямые команды вызова проверяются перед запуском. В поле **Пауза между действиями ИИ** можно задать интервал от 100 до 5000 мс; он сохраняется в настройках, и ожидание прерывается кнопкой остановки. В отдельной панели и консоли появляются краткие наблюдения, выбранные действия и заметки об изменении экрана, без скрытых рассуждений модели. В режимах OpenAI API и Ollama каждый проход отправляет очередной запрос выбранной модели.

Необученная Torch-сеть выбирает случайные касания, прокрутку или «Назад» и не понимает смысл экрана. Она не умеет сама придумать содержательную команду или план; полный набор действий исследования доступен моделям OpenAI API и Ollama, которые поддерживают вызов инструментов.

## Режим OpenAI API

Переключите режим на **OpenAI API**, укажите API key и доступную vision-модель. Ключ используется только в памяти до закрытия приложения. В этом режиме модель анализирует кадр телефона и понимает русские и английские команды; отправленные кадры учитываются API как входные данные.

## Локальная vision-модель через Ollama

Установите актуальную версию [Ollama](https://ollama.com/download), затем скачайте модель, например `ollama pull qwen3-vl:4b`. В программе выберите **Ollama / Qwen**, оставьте адрес `http://localhost:11434` и укажите тег скачанной модели. Qwen3-VL принимает изображения и умеет вызывать инструменты; управление идёт на локальный сервер Ollama без API-ключа. Модель требует достаточно оперативной памяти и места на диске; список размеров и требования смотрите на [странице Qwen3-VL](https://ollama.com/library/qwen3-vl).

## Необученная модель через PyTorch

Установите PyTorch командой `python -m pip install -r requirements-torch.txt`. Выберите режим **Torch / случайная модель**, затем нажмите **Исследовать экран**. При первом запуске создаётся небольшая свёрточная нейросеть со случайными начальными весами: ей не нужны API-ключ, интернет, Hugging Face или готовая модель. После действия программа сравнивает кадры и использует величину визуального изменения как простой сигнал обучения. Веса сохраняются в отдельный файл `torch_brain.pt`. Кнопка **Открыть…** позволяет загрузить другой совместимый файл `.pt`, а **Сохранить модель в новый .pt…** задаёт другой файл для весов. История распознанных экранов хранится отдельно в JSON. PyTorch находит CUDA автоматически, если совместимая видеокарта доступна, иначе работает на CPU.

Случайная модель не понимает русский текст и не распознаёт назначение кнопок; OCR и словарь лишь отдельно показывают распознанные подписи. Поэтому это стартовая заготовка для экспериментов и обучения, а не готовый собеседник или надёжный исследователь интерфейса. Сигнал по изменению изображения также не означает, что модель поняла, что произошло.

Флажок **Полная автономия** открывает произвольные команды `adb shell` и Fastboot в обычном режиме ИИ; он выключен по умолчанию. Режим любопытства включает эти инструменты автоматически. Доступ к инструментам не требует дообучения API модели, если выбранная модель поддерживает вызовы tools. В локальном режиме разрешение включает явный ввод shell/Fastboot команд и их использование в сохранённых правилах, но локальный мозг остаётся набором правил и не может самостоятельно рассуждать или анализировать экран.

## Границы отображения и кнопок

scrcpy передаёт изображение, пока Android работает и подключение USB debugging авторизовано. В Fastboot/bootloader и Recovery поток scrcpy недоступен; приложение очищает экран и показывает сообщение, а после загрузки Android запускает поток снова. Для изображения в Fastboot нужна отдельная поддержка конкретного производителя/загрузчика или внешняя HDMI/USB capture система.

Долгое нажатие на элемент экрана отправляется как ADB swipe в одну точку на заданное время. Удержание аппаратной клавиши отправляется как синтетический Android long-press key event; оно не эквивалентно физически зажатой кнопке на каждом устройстве. Если телефон выключен, завис до запуска ADB или требует аппаратную комбинацию для входа в загрузчик, ADB не сможет нажать физические клавиши за пользователя.

Снимки защищённого содержимого, например некоторых DRM видео и защищённых экранов, Android может возвращать чёрными. Возможность переключать мобильные данные или Wi-Fi зависит от версии Android, прошивки и разрешений.

В обычном API режиме AI не получает произвольную командную оболочку. Включение полной автономии намеренно расширяет доступ до shell/Fastboot команд. Перед отправкой задач учитывайте, что экранные кадры передаются внешнему API для анализа.

Для кнопок интерфейса используются локальные PNG-значки из [репозитория Google Material Design Icons](https://github.com/google/material-design-icons); файлы лицензии находятся в `assets/material-icons/LICENSE.txt`. Значки загружаются с приложением и не требуют сети при запуске.
